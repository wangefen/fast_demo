📂 config 目录

涉及模块：config/config.go + config/config.yaml — 配置文件与读取

config.yaml

存放配置数据（应用名、端口、数据库连接信息等）。纯文本 YAML 格式，改完重启程序即可生效，无需重新编译。

config.go

用 Go 代码把 config.yaml 的内容加载到内存。这是源码，改完需要重新编译才能生效。

两者的区别
文件存什么改了之后
config.yaml配置值（端口、密码等）重启即可
config.go读取配置的逻辑代码需重新编译

🧱 Go 结构体（struct）与全局变量

涉及模块：config/config.go — Config 结构体定义

type Config struct 的作用

定义一个数据结构模板，映射 config.yaml 里的配置字段。结构体每个字段对应一个配置项，代码里通过 config.App.Port 这样清晰的方式取值，不用手动解析字符串。

AppConfig = &Config{} 的作用

声明一个全局变量，初始化为空的 Config 实例（& 取地址，所以是指针）。程序启动时从 YAML 加载数据填进去，后续任何地方直接用 AppConfig 就能拿到配置值。

🧱 Go 结构体小细节

涉及模块：config/config.go — 嵌套结构体与 yaml 标签

结构体嵌套（结构体里套结构体）

Config 里直接定义 App 和 Database 两个匿名结构体，省去单独定义类型。访问方式不变：config.App.Name。

yaml 标签匹配规则

Go 结构体字段名大写（如 Dsn），YAML 里是小写（dsn），不加标签会匹配不上。解决：在字段后加 yaml:"dsn" 标签。

🌐 Gin 框架

*gin.Engine 是什么

Gin 框架的核心引擎实例，* 表示指针。

它的作用

可以理解成整个 Web 服务的"路由器 + 处理器"总管：

  • 注册路由 — 用户访问 /login 等地址时该执行哪段代码

🔐 JWT（JSON Web Token）

涉及模块：controllers/auth_controller.go — 注册/登录接口

JWT 是什么

JWT 是一种令牌（Token）格式，用于在客户端和服务器之间安全地传递信息。它本质上是一串加密后的字符串，包含了用户的部分信息。

可以理解成：一张带签名的电子通行证。服务器发给你，你每次来的时候亮一下，服务器验证签名没问题就放行。

为什么需要 JWT

HTTP 是无状态的，意思是服务器处理完一次请求就"忘了"你是谁。那怎么让服务器记住登录状态？

传统做法是 Session：用户登录后，服务器存一份 session 记录，返回一个 session_id 给浏览器。但这样服务器要维护大量 session，分布式部署时更麻烦。

JWT 的做法是：用户信息加密后直接发给客户端保存，服务器不存任何登录记录。客户端每次请求带上 JWT，服务器验证签名通过就知道你是谁。

好处：服务器不需要存 session，省内存，分布式部署也方便。

JWT 的结构

一个 JWT 看起来像这样三部分组成，用点隔开：

xxxxx.yyyyy.zzzzz

  • Header（头部） — 说明用了什么加密算法（比如 HS256）
  • Payload（载荷） — 存放实际数据，比如用户 ID、用户名、过期时间等
  • Signature（签名） — 用服务器的密钥对前面两部分签名，防止数据被篡改

关键点：Payload 只是 base64 编码，不是加密的，任何人都能解码看到内容，所以不要放密码等敏感信息。真正防篡改的是签名部分。

JWT 的工作流程

以登录为例：

  1. 用户输入用户名密码 → 发送给服务器
  2. 服务器验证用户名密码正确 → 生成一个 JWT（包含用户 ID、过期时间等），返回给客户端
  3. 客户端收到 JWT 后存起来（通常是 localStorage 或 Cookie）
  4. 后续每次请求，客户端把 JWT 放在 HTTP Header 里发过来
  5. 服务器收到请求，验证 JWT 签名有效、没有过期 → 从 JWT 里取出用户 ID，处理请求
  6. JWT 过期了 → 用户需要重新登录
在项目里怎么用 JWT

需要一个 JWT 相关的工具包，通常放在 utils 或独立的 auth 包里，包含三个函数：

  • 生成 Token — 用户登录成功时调用，传入用户 ID，返回 JWT 字符串
  • 解析/验证 Token — 从请求头里取出 JWT，验证签名和过期时间，取出用户 ID
  • 中间件 — 写一个 Gin 中间件，在每个需要登录的接口前自动执行验证，没通过的直接拦截

项目中的注册/登录流程加上 JWT 后就是：

注册：接收用户名密码 → 加密密码 → 存数据库 → 生成 JWT 返回给用户

登录：接收用户名密码 → 查数据库 → 比对密码 → 生成 JWT 返回给用户

访问需要登录的接口：客户端带上 JWT → 中间件验证 JWT 有效 → 处理请求

🔍 Go 中的 error 类型与 GORM 的 .Error

涉及模块：utils/utils.go + controllers/auth_controller.go — HashPassword 返回值、Create().Error

为什么 Create(&user) 后面要加 .Error

global.Db.Create(&user) 返回的是 *gorm.DB，不是 error。gorm.DB 结构体里有一个 .Error 字段用来存错误。所以需要加 .Error 才能取出真正的错误。

对比两种写法：

写法返回类型效果
gorm.Open(...)(*gorm.DB, error)直接拿 err 判断
global.Db.Create(&user)*gorm.DB需要加 .Error 才能拿到错误
if 中使用 := 声明变量的作用域

在 if err := xxx; err != nil { ... } 中，err 的作用域只在 if 块内。if 块结束后 err 就不可见了。

如果 if 里出错了但没写 return，函数不会自动结束，会继续往下执行。所以即便 if 后面暂时没代码，也建议写上 return 养成习惯。

error 是什么

error 是 Go 内置的接口类型，不是空接口，也不是参数类型。它的定义是：

type error interface { Error() string }

也就是说，任何类型，只要实现了 Error() string 这个方法，就能当 error 用。

error 和空接口 interface{} 的区别
errorinterface{}（空接口）
能放什么只有实现 Error() 方法的类型任意类型
能否放 int❌✅
能否放 string❌✅
能否放 error 对象✅✅
err.Error() 的作用

err 本身是 error 接口类型，不是字符串。err.Error() 就是调用 error 接口自带的这个方法，把错误信息转成字符串让你看到。

为什么在 ctx.JSON() 里要用 err.Error() 而不是直接传 err？因为 gin.H 是 map[string]interface{}，直接传 err 进去序列化成 JSON 时可能输出空对象 {} 或 null，而传 err.Error() 是确定的字符串，一定能正确输出为 {"error": "错误信息"}。

error 能用做变量名吗

不能。error 是 Go 的预定义标识符（类似 string、int、nil、true），用作变量名会导致编译错误。

🛠️ ShouldBindJSON 和 AutoMigrate

涉及模块：controllers/auth_controller.go — 注册接口

ShouldBindJSON

ctx.ShouldBindJSON(&user) 自动读取 HTTP 请求的 JSON 请求体，按字段名匹配解析到你指定的结构体里。

  • JSON 比结构体多字段 → 忽略，不报错
  • JSON 比结构体少字段 → 结构体对应字段留零值（string=""，int=0），不报错
  • JSON 字段类型不匹配 → 报错
AutoMigrate

global.Db.AutoMigrate(&user) 自动检查数据库，保证表结构和结构体一致：

  • 表不存在 → 自动创建
  • 缺字段 → 自动新增列
  • 不会删字段、不会改类型（防止丢数据）

注意：AutoMigrate 不应该放在每个请求里执行（比如注册接口），应该在项目启动时执行一次就够了。

🌐 项目常用分层

涉及模块：全部 — 项目架构说明

典型的 Web 项目分层结构：

层作用
controller接收 HTTP 请求，调用 service 处理，返回响应
service写业务逻辑
model定义数据库表结构，对接数据库（CRUD）
global存放整个项目共用的全局变量（Db、配置等）
config加载配置文件（YAML 等）
model 层的作用

定义结构体对应数据库表，配合 GORM 自动建表、增删改查。每个结构体 = 一张表。

gorm.Model

GORM 内置的四个基础字段：ID（主键）、CreatedAt、UpdatedAt、DeletedAt（软删除）。直接内嵌到自定义结构体中。

AutoMigrate 自动建表

只定义结构体不会自动建表，需要在启动时调用 global.Db.AutoMigrate(&model.User{})。GORM 会自动创建/补充字段，不会删表或删列。

global 包

存放整个项目都能访问的全局变量（如 global.Db），避免每个文件各自维护一个连接。只放真正全局只需要一份的东西。
