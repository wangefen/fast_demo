🔐 JWT 学习笔记

utils/utils.go — GenerateJWT 函数逐行解析

📄 完整代码

// GenerateJWT 生成一个 JWT 令牌，包含用户名和过期时间
func GenerateJWT(username string) (string, error) {
    token := jwt.NewWithClaims(jwt.SigningMethodHS256, jwt.MapClaims{
        "username": username,
        "exp":      time.Now().Add(time.Hour * 72).Unix(),
    })

    signedToken, err := token.SignedString([]byte("secret"))
    return "Bearer " + signedToken, err
}

📌 第 17 行 — 函数声明

17 func GenerateJWT(username string) (string, error)
作用：定义了一个名为 GenerateJWT 的函数，接收一个 username 字符串，返回两个值：生成的 JWT 字符串 和 可能的错误。

为什么返回值要两个？Go 的习惯是"返回结果 + 错误"，如果成功了 err 就是 nil，如果失败了就返回错误信息。

📌 第 18 行 — 创建 JWT（核心）

18 token := jwt.NewWithClaims(jwt.SigningMethodHS256, jwt.MapClaims{"username": username, "exp": ...})
这行在做什么？

创建一个新的 JWT 令牌，指定了"签名方式"和"要携带的数据（claims）"。


拆开看三个部分：
部分值说明
jwt.NewWithClaims() 构造函数 创建一个新的 JWT token 对象。来自 github.com/golang-jwt/jwt 包
jwt.SigningMethodHS256 签名算法 HS256 = HMAC + SHA256，对称加密。同一个密钥既用来签名也用来验证。适合大多数项目
jwt.MapClaims{...} 载荷（数据） 一个 map，里面放你想存在 JWT 里的数据。key 是字符串，value 可以是任意类型
什么是 claims？

Claims 就是 JWT 里存放的信息，分为三种：

  • 注册 claims — 标准字段，比如 exp（过期时间）、iss（签发者）、sub（主题）
  • 公共 claims — 自定义字段，比如 username、role、user_id
  • 私有 claims — 双方约定的字段

jwt.MapClaims 是什么？

Golang 里 map[string]interface{} 类型的别名，意思是你可以在里面放任何自定义数据。比如我们放了 "username" 和 "exp"。

官方文档 jwt.NewWithClaims 文档 SigningMethodHS256 文档 MapClaims 文档

📌 第 19 行 — 添加 username 到载荷

19 "username": username,
作用：把用户名存到 JWT 的 payload 里。

为什么要放 username？服务器收到这个 JWT 时，不需要查数据库就知道是哪个用户。但注意：Payload 只是 base64 编码，不是加密的，所以不要放密码。

还能放什么？比如 user_id、role（角色）、email 等，根据需要来。

📌 第 20 行 — 设置过期时间

20 "exp": time.Now().Add(time.Hour * 72).Unix()
作用：设置这个 JWT 的过期时间，这里是 72 小时（3 天）后过期。

拆开看：
  • time.Now() — 当前时间
  • .Add(time.Hour * 72) — 加上 72 小时
  • .Unix() — 转成 Unix 时间戳（自 1970-01-01 起的秒数）

为什么要有过期时间？防止 JWT 泄露后永远有效。过期后用户需要重新登录。72 小时是示例，实际项目可能设为 15 分钟（短期）到 7 天不等。

time.Add 文档 time.Unix 文档

📌 第 22 行 — 签名生成最终 Token

22 signedToken, err := token.SignedString([]byte("secret"))
作用：用密钥对 JWT 进行签名，生成最终的 token 字符串。

拆开看：
  • token.SignedString() — 用密钥对前面创建的 token 进行签名，输出最终的 JWT 字符串
  • []byte("secret") — 把密钥字符串转成字节数组。"secret" 是密钥（这里是写死的，实际项目应该放在配置文件里）

签名的意义：密钥只有服务器知道，所以如果有人篡改了 JWT 里的内容，服务器验证签名时会发现对不上，直接拒绝。这就保证了 JWT 的完整性。

为什么用 []byte？SignedString 方法要求传入 []byte 类型，所以需要字符串转一下。

官方文档 SignedString 文档

📌 第 23 行 — 返回结果

23 return "Bearer " + signedToken, err
作用：返回最终的 JWT 字符串和错误信息。

为什么加 "Bearer "？这是 HTTP 协议的标准做法，表示"我是一个 Bearer token"。客户端在请求头里应该这样发：Authorization: Bearer <token>

注意：这里返回的 "Bearer " + signedToken 中间有空格，最终结果类似 "Bearer eyJhbGciOiJI..."

🔄 整体流程总结

GenerateJWT 函数做了什么：
  1. 收到一个 username
  2. 创建 JWT 的 header（指定用 HS256 算法）和 payload（放入 username 和过期时间）
  3. 用密钥 "secret" 对整个内容进行签名
  4. 返回 "Bearer 签名字符串"

调用的地方大概是这样：
// 在 auth_controller.go 中，用户登录成功后调用 tokenString, err := utils.GenerateJWT(user.Username) if err != nil { // 处理错误 } // 把 tokenString 返回给前端 ctx.JSON(http.StatusOK, gin.H{"token": tokenString})

❓ 常见问题

为什么我生成的 JWT 这么长？

JWT 由三部分（Header + Payload + Signature）经过 base64 编码后拼接而成，每部分都挺长，所以整体看起来像一长串乱码。这是正常的。

HS256 和 RS256 有什么区别？
  • HS256 — 对称加密，同一个密钥既签名也验证。简单，适合单服务
  • RS256 — 非对称加密，私钥签名、公钥验证。适合微服务场景（验证服务不需要知道签名密钥）
密钥 "secret" 写死在代码里可以吗？

不行。密钥应该放在配置文件（config.yaml）或者环境变量里，不要写死在代码中。否则代码泄露密钥也跟着泄露，任何人都能伪造 JWT。

JWT 过期了怎么办？

客户端收到 401 未授权响应后，引导用户重新登录。也可以实现"刷新令牌"（refresh token）机制，用长期有效的 refresh token 去换取新的短期 access token，这样用户不用频繁登录。
